# وحدة التدقيق والمراقبة (Audit Module - Overview)

## الغرض (Purpose)

وحدة التدقيق هي "الصندوق الأسود" للنظام. توفر سجلاً تاريخياً غير قابل للتعديل (Immutable) وبنمط الإضافة فقط (Append-Only) للإجابة على الأسئلة: من قام بالإجراء؟ ماذا حدث؟ متى؟ وأي كيان تأثر؟ وما هي التغييرات الفنية؟ الوحدة مصممة للامتثال الأمني وتتبع مسار العمليات الجوهرية.

## الحالة (Status)

مرحلة التأسيس مكتملة (Schema & ALS Integration). جاري التحضير لتنفيذ واجهة الإدارة (Admin Dashboard) ونظام إعادة الإرسال (Event Forwarding).

## المبادئ المعمارية المعتمدة (Architectural Principles)

1. **الوصول المباشر لقاعدة البيانات (Direct DB Access):** لا يوجد أي استخدام للكاش (Caching). تُسترجع السجلات عبر استعلامات PostgreSQL المباشرة مع الاعتماد على الفهارس (Indexes) والتصفح المقسم (Pagination).
2. **عدم تتبع الأجهزة (No Device/Location Tracking):** النظام يعتمد فقط على معرف المستخدم (`actorId`) ومعرف الطلب (`reqId`). حقول `ipAddress` و `userAgent` متوفرة في المخطط (Schema) كحقول محجوزة للاستخدام المستقبلي (Forensic) ولا تُستخدم حالياً.
3. **المعالجة الخلفية المدمجة (In-Process Processing):** لا نستخدم طوابير خارجية (مثل Redis Queues). الأحداث تُسجل إما بشكل متزامن داخل المعاملات (Transactions) أو كعمليات غير متزامنة مدمجة (Fire-and-Forget). نظام الإرسال الخارجي (Forwarding) يعتمد على `node-cron` وأقفال PostgreSQL (Advisory Locks).
4. **تخطي الحارس الصامت (Bypassing Silent Guardian):** عند استرجاع سجلات التدقيق، يجب تخطي فلتر الحذف المنطقي (Soft Delete) لمعرفة هوية المستخدمين المحذوفين الذين نفذوا الإجراءات سابقاً.
