# قواعد وحدة التدقيق (Audit Rules)

> [!CAUTION]
> لا تتجاوز هذه القواعد تحت أي ظرف لضمان سلامة السجل التاريخي والتوافق مع القرارات المعمارية.

1. **لا تحديث ولا حذف (No Update, No Delete):**
   - يُمنع منعاً باتاً كشف أي نقطة نهاية (Endpoint) أو دالة برمجية تقوم بتعديل أو حذف أي سجل تدقيق موجود. الجدول `Append-Only` بالكامل.

2. **تطهير البيانات إلزامي (Mandatory Sanitization):**
   - يجب أن تمر جميع كائنات الـ Payload المُدخلة بعملية تطهير (Sanitization) عميقة لإزالة البيانات الحساسة (كلمات المرور، الرموز) قبل تخزينها في قاعدة البيانات ضمن `newValues` أو `oldValues` أو `metadata`.

3. **لا تتبع للأجهزة حالياً (No Explicit Device Tracking):**
   - لا تقم ببرمجة أو استخراج أي بيانات تخص الـ `ipAddress` أو الـ `userAgent` من كائن الطلب (Request) لحقنها في التدقيق. هذه الحقول موجودة في قاعدة البيانات "كحقول محجوزة للاستخدام المستقبلي" فقط وستكون قيمتها `null` حالياً.

4. **تخطي الحذف المنطقي عند الاسترجاع (Retrieval & Soft Delete Bypass):**
   - عند عرض سجلات التدقيق للمديرين، يجب أن يتجاوز `AuditRepository` فلتر الحذف المنطقي (Soft Delete) للمستخدمين. إذا تم حذف الحساب الذي قام بإجراء عملية، يجب أن يظل اسمه وهويته واضحين في سجل التدقيق.

5. **منع الطوابير الخارجية (No External Queues):**
   - يُمنع استخدام Redis Queues، BullMQ، RabbitMQ أو أي نظام رسائل خارجي لمعالجة أو تصدير سجلات التدقيق.
   - يعتمد تصدير الأحداث حصرياً على جدولة داخلية (In-Process) عبر `node-cron` وأقفال `PostgreSQL Advisory Locks`.

6. **تغليف الاستدعاءات غير المتزامنة (Fire-and-Forget Safety):**
   - إذا تم استدعاء دالة `logEvent` خارج إطار معاملة قاعدة بيانات (Without `tx`)، يجب حماية الاستدعاء بالغلاف الصارم `try-catch` لضمان عدم توقف عملية الـ Node.js بسبب أخطاء `UnhandledRejection`.

7. **لا تخزين مؤقت (No Caching):**
   - تُمنع أي آليات للتخزين المؤقت (Redis, Memory) عند قراءة بيانات سجل التدقيق. تعتمد القراءة مباشرة على استعلام قاعدة البيانات المباشر (Direct DB Access).

8. **تطبيق العزل المناطقي الإلزامي (Mandatory Branch Enforcement):**
   - يجب على المتحكمات (Controllers) عدم الثقة في المعاملات المرسلة في مسار الـ URL (`req.query`). إذا لم يكن لدى المستخدم صلاحية القراءة العامة (`read:audit:any`)، يجب فرض كتابة `query.branchId = req.user.branchId` بشكل إجباري قبل إرسال الطلب إلى الـ Repository لمنع التسريب عبر الفروع (Cross-Branch Data Leakage).
