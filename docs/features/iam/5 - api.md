# وثائق واجهة برمجة تطبيقات إدارة الهوية والوصول (IAM API)

#### 1. مسارات المصادقة والجلسات (`/api/v1/auth`)

مخصصة للتعامل مع مزود الهوية (Google) وإدارة الجلسات المادية في قاعدة البيانات.

| **الطريقة** | **المسار (Path)**  | **الغرض**                                                               | **يتطلب مصادقة (Access Token)** |
| ----------- | ------------------ | ----------------------------------------------------------------------- | ------------------------------- |
| `GET`       | `/google`          | توجيه المشغل إلى شاشة مصادقة Google (يقبل `deviceId` في الـ Query)      | لا                              |
| `GET`       | `/google/callback` | مسار العودة لاستلام الرمز وإنشاء الجلسة وتهيئة الـ Cookie               | لا                              |
| `POST`      | `/refresh`         | تدوير الرموز (إرسال رمز جديد بناءً على الـ Refresh Token في الـ Cookie) | لا (يعتمد على Cookie)           |
| `POST`      | `/logout`          | الحذف الفيزيائي لسجل الجلسة من قاعدة البيانات                           | نعم                             |

#### 2. مسارات الدعوات والانضمام (`/api/v1/invitations`)

البديل التشغيلي الآمن لمسار "التسجيل الحر". لا يدخل أحد النظام إلا بدعوة محددة الصلاحيات والفرع.

| **الطريقة** | **المسار (Path)** | **الغرض**                                                                          | **الصلاحية المطلوبة (RBAC)**        |
| ----------- | ----------------- | ---------------------------------------------------------------------------------- | ----------------------------------- |
| `POST`      | `/`               | إصدار دعوة جديدة لموظف (تُرسل عبر البريد الإلكتروني)                               | `create:invitation:any` أو `branch` |
| `GET`       | `/`               | سرد الدعوات المعلقة                                                                | `view:invitation:any` أو `branch`   |
| `DELETE`    | `/:inviteId`      | إبطال دعوة قبل أن يقبلها الموظف (يُحوّل الحالة إلى `REVOKED` ولا يحذفها فيزيائياً) | `delete:invitation:any` أو `branch` |

#### 3. مسارات المستخدمين والتشغيل (`/api/v1/users`)

تُطبق جميع هذه المسارات فلترة صامتة في طبقة Prisma (عبر الـ ALS) لضمان عدم تجاوز الموظف لنطاق فرعه (`branchId`) إلا إذا كان يمتلك نطاق `:any`.

| **الطريقة** | **المسار (Path)**  | **الغرض**                                                                       | **الصلاحية المطلوبة (RBAC)**   |
| ----------- | ------------------ | ------------------------------------------------------------------------------- | ------------------------------ |
| `GET`       | `/me`              | جلب كائن المشغل الحالي مع مصفوفة صلاحياته (لشحن الفرونت إند)                    | نعم (أي توكن صالح)             |
| `GET`       | `/`                | سرد الموظفين النشطين (يُستبعد المؤرشفين تلقائياً)                               | `read:users:any` أو `branch`   |
| `GET`       | `/:userId`         | جلب بيانات موظف معين                                                            | `read:users:any` أو `branch`   |
| `PATCH`     | `/:userId/status`  | تفعيل أو إيقاف المستخدم (`isActive`). الإيقاف يطرد الجلسات فوراً                | `update:users:status`          |
| `POST`      | `/:userId/restore` | **الاستعادة (Restore):** استعادة حساب مؤرشف (تعيين `deletedAt: null`)           | `update:users:status`          |
| `DELETE`    | `/:userId`         | **الأرشفة الآمنة (Soft Delete):** تحديث `deletedAt` دون المساس بالسجلات المالية | `delete:users:any` أو `branch` |

#### 4. مسارات الأدوار الديناميكية (`/api/v1/roles`)

لإدارة هيكل الصلاحيات وترقية أرقام الإصدارات لإجبار التحديث الصامت.

| **الطريقة** | **المسار (Path)** | **الغرض**                                                 | **الصلاحية المطلوبة (RBAC)** |
| ----------- | ----------------- | --------------------------------------------------------- | ---------------------------- |
| `GET`       | `/`               | سرد جميع الأدوار الوظيفية المتاحة                         | `view:role:any`              |
| `POST`      | `/`               | إنشاء دور وظيفي جديد (وتعيين مستوى `level` له)            | `create:role:any`            |
| `PUT`       | `/:roleId`        | تعديل صلاحيات دور موجود (يرفع رقم الـ `version` تلقائياً) | `update:role:any`            |
